## 1. End-to-End Pipeline Mapping (`SLUS-21351` -> Metal PBR)

On retail PS2 (`SLUS-21351`), geometry and lighting are split between Emotion Engine (`SLUS_213.51`), VU1 microprograms, and Graphics Synthesizer (`GS`) fixed-function blending. In **Rockport 2026 Native Metal**, each PS2 structure maps directly onto modern GPU buffers and Cook-Torrance GGX + Dual-Lobe Automotive Clearcoat shaders (`native_metal/Shaders.metal`):

```text
PS2 SLUS-21351 Source                       Bridge / Export Layer                      native_metal/Shaders.metal
───────────────────────────────────────────  ─────────────────────────────────────────  ──────────────────────────────────────────
eSolid (0x00134011) + VIF (0x00134A02)  ──▶  Y-up meter transform, UV unswap, R-LFSR  ──▶  Vertex Stage (RockportVertex @ buffer(0))
                                             ADC strip -> indexed triangle list            + per-draw modelMatrix / materialId
SunInfos (0x00034202) + ELF .data       ──▶  Z-up -> Y-up dir + GS alpha (128 -> 1.0) ──▶  RockportSunUniforms @ buffer(1/2)
VLT visuallook (ATTRIBUTES.BIN)         ──▶  Bloom tint, desat, black-bloom lift      ──▶  RockportVisualLookUniforms + HDR Post-FX
eLightMaterial (0x00135200, 156 mats)   ──▶  Power->Roughness, Metallic, Clearcoat    ──▶  RockportPBRMaterial @ buffer(3) / LUT
```

## 2. Coordinate Space & Vertex Layout Bridge (`eSolid` -> Metal)

### 2.1 Coordinate System Transform (PS2 Z-Up Left-Handed -> Metal Y-Up Right-Handed)

PS2 NFSMW stores vehicle and world geometry in **Z-up** meters (quantized in `0x00134A02` at `scale = 0.0002` m for cars and `1/256` m for frontend platforms). `native_metal/` uses **Y-up right-handed** coordinates in meters:

$$\begin{aligned}
x_{\text{metal}} &= x_{\text{ps2}} \\
y_{\text{metal}} &= z_{\text{ps2}} \\
z_{\text{metal}} &= -y_{\text{ps2}}
\end{aligned}$$

The exact same basis rotation applies to vertex normals (`(nx, nz, -ny)`, re-normalized) and `SunInfos` sun vectors (`SunChunkInfo.Position` `[X, Y, Z]` -> `normalize(float3(X, Z, -Y))`).

### 2.2 PS2 VIF Unpacking Rules Preserved by the Bridge

1. **4-Blocked Quantized Positions (`VU1 addr 0x05..0x1C`):** `pos_ps2 = origin + q_int16 * scale` where `scale` is `v1[1]` (`float32`).
2. **VU1 Odd-Vertex UV Unswap (`VU1 addr 0x1D..0x4C`):** Odd strip vertices (`i & 1`) store transposed `(v_raw, u_raw)`; after unswapping, `uv = (u_int16 / 4096.0, 1.0 - v_int16 / 4096.0)`.
3. **23-Bit LFSR `ADC` Strip Restart (`RINIT`/`RNEXT`):** Triangle strip restart bits decoded from `v1[0], v1[2], v1[3]` drop restart triangles (`adc == 1`) and emit clean counter-clockwise triangle lists grouped by `(eStripEntry.texture_index, eStripEntry.light_material_index)`.

### 2.3 Canonical Metal Vertex Layout (`RockportVertex`)

Each submesh batch carries a `material_hash` (`0x00134013` `LightMaterial` table entry indexed by `eStripEntry.light_material_index`) and `texture_hash` (`0x00134012` entry indexed by `eStripEntry.texture_index`):

| Attribute | Metal `[[attribute(n)]]` | Type | Offset | Size | Source |
| :--- | :---: | :--- | ---: | ---: | :--- |
| `position` | `0` | `float3` | `0` | `12` | Transformed `(x_ps2, z_ps2, -y_ps2)` meters |
| `normal` | `1` | `float3` | `16` | `12` | Transformed & normalized `(nx_ps2, nz_ps2, -ny_ps2)` |
| `texcoord` | `2` | `float2` | `32` | `8` | Unswapped `(u, v)` |
| `color_ao` | `3` | `float4` | `40` | `16` | Optional vertex AO / damage / tint (`1,1,1,1` default) |

*(Compact 48-byte packed stride when `float3` is stored packed as `packed_float3`, or 64-byte SIMD-aligned stride when `simd_float3` = 16 B is used in shared C++/Metal headers. `Rockport2026Lighting.h` uses explicit `float4` vectors for all cross-API uniform/material structs so C23/C++20 and Metal 3 layouts match byte-for-byte with zero compiler-padding surprises!)*

## 3. Shared C / C++20 / Metal Uniform & Material ABI (`Rockport2026Lighting.h`)

All shared structures generated by `tools/decomp_bridge.py` use **16-byte aligned `float4` fields** (no bare `float3` alignment ambiguity between C++, Swift `simd`, and Metal Shading Language).

### 3.1 `RockportSunUniforms` (80 bytes, `SunInfos` + `SLUS_213.51` Rig)

```c
struct RockportSunUniforms {
    float4 sun_direction_intensity; // xyz = Y-up unit dir toward sun, w = primary intensity (default 6.5 / normalized HDR)
    float4 sun_color_size;          // rgb = linear solar disc color (from SunLayers[0]), w = angular disc size
    float4 corona_color_intensity;  // rgb = linear halo/corona color (from SunLayers[1]), w = halo intensity
    float4 ray_color_intensity;     // rgb = linear ray scatter color (from SunLayers[2]), w = ray intensity
    float4 fill_color_intensity;    // rgb = ELF FillLightDiffuseColour [0.87,0.90,1.00], w = FillLightDiffuseIntensity (2.1)
};
```

Exact preset mappings exported into `Rockport2026Lighting.h`:

  - `SunLayers[1]` (`[175, 215, 255, 128]`, `IntensityScale = 0.45`) -> clean sky-blue atmospheric corona.
- **`golden_hour` (`patches/lighting/rockport2026_golden_hour.json`):**
  - `SUNSET`/`MIDDAY` `Position = [5200, -1400, 1150]` -> Y-up `[5200, 1150, 1400]` -> normalized `sun_direction = [0.9445, 0.2089, 0.2543]` (~12.1° low golden-hour elevation for dramatic fender rim highlights!).
  - `SunLayers[0]` (`[255, 236, 178, 128]`, `IntensityScale = 1.35`, `Size = 78.0`) -> warm luminous gold-white solar core.
  - `SunLayers[1]` (`[255, 178, 86, 128]`, `IntensityScale = 0.72`) -> amber-gold atmospheric corona.

### 3.3 `RockportPBRMaterial` (64 bytes, 1:1 `eLightMaterial` -> Metal PBR)

```c
struct RockportPBRMaterial {
    uint32_t name_hash;          // EA bStringHash (e.g. 0xc2462169 for METPAINTBLUE)
    uint32_t pbr_category;       // Enum RockportMaterialCategory (0..13)
    float    roughness;          // GGX perceptual roughness [0.04, 0.96]
    float    metallic;           // Conductor/flake metallic factor [0.0, 1.0]
    float4   base_color_alpha;   // rgb = DiffuseMaxRGB * DiffuseMaxScale (normalized), a = DiffuseMaxA
    float4   clearcoat_ior_spec; // x = clearcoat [0..1], y = clearcoat_roughness, z = IOR (1.50 paint/glass), w = envmap_boost
    float4   emissive_flags;     // rgb = HDR emissive radiance (>= 0), w = packed flags (flake/transparent/emissive)
};
```

## 4. `eLightMaterial` -> 2026 Cook-Torrance PBR Translation Formulas

Retail `SLUS-21351` `GLOBALB.BUN` defines **156 `eLightMaterial` entries** (`0x00135200`), each parameterized by empirical PS2 Phong + GS environment-map scalars (`DiffuseMin/Max`, `SpecularPower`, `SpecularMin/MaxScale`, `EnvmapPower`, `EnvmapMin/MaxScale`, `MetallicScale`, `SpecularHotSpot`).

`tools/decomp_bridge.py` translates every PS2 `LightMaterial` deterministically into physically grounded 2026 PBR parameters using the rules below:

### 4.1 Roughness (`roughness` $\in [0.04, 0.96]$)

PS2 `SpecularPower` (typically `0.3` to `8.0`) behaves as a compact normalized specular exponent, while `EnvmapMaxScale` (`0.0` to `3.0`) indicates mirror sharpness:

1. Convert PS2 `SpecularPower` into an effective Blinn-Phong shininess $N_{\text{eff}} = 2.0 + \text{SpecularPower} \times 18.0$.
2. Convert shininess to GGX perceptual roughness:
   $$\alpha_p = \sqrt{\frac{2.0}{N_{\text{eff}} + 2.0}}, \qquad \text{roughness}_{\text{base}} = \operatorname{clamp}(\alpha_p,\; 0.04,\; 0.96)$$
3. Apply physically based category calibration:
   - **Mirror Chrome / Polished Glass** (`CHROME`, `MAGCHROME`, `USER_RIMS_CHROME`, `MIRROR`, `WINDSHIELD*`, `HEADLIGHTGLASS`, `BRAKELIGHTGLASS`, `CLEARPLASTIC`): `roughness = clamp(roughness_base * 0.28, 0.04, 0.14)`.
   - **Automotive Clearcoat & Pearl Paints** (`METPAINT*`, `REGPAINT*`, `PEARL*`, `RIMPEARL*`, `CUSTOMPAINT*`, `USER_SPOILER`): underlying basecoat `roughness` is `0.18–0.34` (`METPAINT*` slightly rougher metallic flake base `0.24–0.32`; `REGPAINT*` smooth `0.18–0.24`), topped by a separate glossy clearcoat lobe (`clearcoat_roughness = 0.05–0.08`).
   - **Brushed / Alloy Metals** (`ALUMINUM`, `MAGSILVER*`, `MAGGUNMETAL`, `USER_RIMS*`, `GOLDROTOR`, `EXHAUST_TIP`, `CALIPER`): `roughness = clamp(roughness_base * 0.55, 0.16, 0.38)`.
   - **Carbon Fiber** (`CARBONFIBER`, `CARBONFIBER2`): weave roughness `0.26` under `clearcoat = 0.75`, `clearcoat_roughness = 0.10`.
   - **Rubber & Tires** (`RUBBER`, `WHEELBLUR`, `CHAR_RUBBER`): `roughness = 0.78–0.85`.
   - **Asphalt Road** (`ROAD`): dry base `roughness = 0.62` (modulated dynamically to `0.08` inside wet puddles by `Shaders.metal`).

### 4.2 Metallic, Clearcoat & IOR (`metallic`, `clearcoat`, `ior`)

| Material Family (Examples from 156 `SLUS-21351` Chunks) | `metallic` | `clearcoat` | `cc_rough` | `ior` | Notes |
| :--- | :---: | :---: | :---: | :---: | :--- |
| **`CHROME`, `MAGCHROME`, `USER_RIMS_CHROME`, `MIRROR`** | `1.00` | `0.00` | `0.05` | `2.50` | Pure conductor Fresnel; Rockport 2026 restores `SpecularMaxScale` glints (`0.0 -> 0.25/0.45`) |
| **`ALUMINUM`, `MAGSILVER*`, `MAGGUNMETAL`, `USER_RIMS*`, `BRAKEDISC`, `GOLDROTOR`, `ENGINE`, `HOSES`** | `0.85–0.95` | `0.15` (gloss rims) / `0.0` | `0.12` | `2.20` | Conductive metallic surfaces; `USER_RIMS_GLOSS` carries `clearcoat = 0.65` |
| **`METPAINT*` (`METPAINTBLUE`, `METPAINTSILVER`, `METPAINTRED`, ...), `PEARL*`, `RIMPEARL*`** | `0.78–0.88` | `1.00` | `0.05` | `1.50` | Dual-lobe automotive paint: metallic micro-flake base + full IOR `1.50` urethane clearcoat |
| **`REGPAINT*` (`REGPAINTWHITE`, `REGPAINTBLACK`, ...), `CUSTOMPAINT_*`** | `0.08–0.18` | `1.00` | `0.06` | `1.50` | Non-metallic solid pigment basecoat + full IOR `1.50` clearcoat |
| **`CARBONFIBER`, `CARBONFIBER2`** | `0.10` | `0.80` | `0.10` | `1.48` | Anisotropic-style twill weave under clear resin coat |

| **`ROAD`, `WHEELBLUR`** | `0.00` | `0.00` | `0.50` | `1.50` | Neutralized `DiffuseMaxRGB` (`[0.90,0.57,0.56] -> [0.96,0.98,1.02]` daylight / `[1.08,0.96,0.85]` golden hour) |
| **`RUBBER`, `MATTEPLASTIC`, `DULLPLASTIC`, `BOTTOM`, `INTERIOR`** | `0.00` | `0.00` | `0.50` | `1.45` | Dielectric matte surfaces |

### 4.3 HDR Emissive (`emissive`)

Materials representing vehicle lamps (`HEADLIGHT`, `HEADLIGHTREFLECTOR`, `BRAKELIGHT`) cannot be expressed solely by PS2 `0..1` diffuse scales in an HDR `RGBA16Float` Metal pipeline. The bridge assigns HDR emissive radiance above the `1.0` bloom threshold:
- **`HEADLIGHT` / `HEADLIGHTREFLECTOR`:** `emissive = [3.80, 4.10, 4.60]` (crisp xenon 6000K white-blue).
- **`BRAKELIGHT`:** `emissive = [4.20, 0.35, 0.22]` (intense crimson LED tailbar glow).
- **`BRAKELIGHTGLASS` / `HEADLIGHTGLASS`:** `emissive = [0.0, 0.0, 0.0]`, transmissive/glossy outer lens (`alpha = 0.35..0.45`, `ior = 1.52`, `clearcoat = 0.90`) sitting over the emitter reflector.

## 5. Verification & Integration Workflow

1. **Regenerate C++20 / Metal Headers & Manifest:**
   ```bash
   python3 tools/decomp_bridge.py --out-dir build/decomp_bridge_wave3
   ```
   *(Runs cleanly with or without `build/symbols_slus21351.txt` present!)*
2. **Outputs Produced in `build/decomp_bridge_wave3/`:**
   - `Rockport2026Config.hpp` — `constexpr` VLT physics/camera/pursuit/visuallook deltas + `SLUS-21351` hook addresses.
   - `Rockport2026Lighting.h` — Shared C/C++/Metal structs + exact `daylight` & `golden_hour` uniforms + PBR material LUT.
   - `bridge_manifest.json` — Complete 156-material PS2-to-PBR mapping + presets + hooks for `native_metal/`, Track A, Track B, and RTX Remix tooling.
3. **Syntax & ABI Validation:**
   - Verified via `python3 -m unittest discover -s tests -p "test_decomp_bridge.py" -v`, which compiles a C++20 `static_assert` validation stub with `clang++ -std=c++20 -Wall -Wextra -fsyntax-only`.
